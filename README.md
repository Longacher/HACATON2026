# «Отклик» — платформа доверительных обращений

MVP платформы анонимных обращений с умной маршрутизацией к профильным специалистам
(ТЗ хакатона «Кубок Федерации»).

## Роли

- **Заявитель** — мобильное приложение **React Native (Expo)**: подача обращения,
  трек-номер, чат со специалистом, оценка. Регистрация не требуется.
- **Оператор / Эксперт / Администратор** — веб-интерфейс **Vite + React + TypeScript**.

## Стек

| Слой | Технологии |
|---|---|
| Backend API | Python 3.11, FastAPI, SQLAlchemy 2, Pydantic v2 |
| БД | PostgreSQL 16 (обращения, статусы, чат, правила маршрутизации) |
| Очереди | RabbitMQ (событийная шина аналитики) |
| Кэш / агрегаты | Redis (rate-limit, живые счётчики дашборда) |
| Вектора | Milvus (похожие обращения, автоклассификация) |
| Граф | Neo4j (связи тикетов: дубли, RELATED_TO, цепочки инцидентов) |
| Фронтенд (роли) | React + TS + Vite |
| Мобильное (заявитель) | React Native + Expo |
| Деплой | docker-compose (api, worker, redis, rabbitmq, milvus, neo4j, db) |

## Запуск (одной командой из чистого клона)

```bash
docker compose up --build
```

Поднимаются: `db`, `redis`, `rabbitmq`, `milvus`, `neo4j`, `api` (с сидом базы),
`worker` (слушает события RabbitMQ: обновляет агрегаты в Redis, индексирует
вектора в Milvus и связи в Neo4j).

- Swagger API: http://localhost:8000/docs
- Health: http://localhost:8000/health

### Локальный запуск (без Docker)

```bash
# Backend
cd backend
python -m venv .venv
.venv\Scripts\activate (Windows) / source .venv/bin/activate (Linux)
pip install -r requirements.txt
python seed.py
uvicorn app.main:app --reload --port 8000

# Worker
python -m app.worker

# Веб (роли)
cd web
npm install
npm run dev              # http://localhost:5173

# Мобильное (заявитель)
cd mobile
npm install
npm start                # Expo Go / эмулятор / web
```

## Модель приватности (ТЗ 06)

- Не запрашиваются имя, почта, телефон, учебное заведение.
- IP-адрес и User-Agent не пишутся в БД и не связываются с обращением
  (rate-limit проверки трек-номера — только in-memory по IP).
- Сторонние трекеры и аналитика отсутствуют.
- Вложения очищаются от EXIF/геометок на сервере (Pillow).
- Сессия не привязывает обращения одного человека друг к другу.
- В аналитику и выгрузки попадают только агрегаты и метаданные, без текстов
  и контактов.
- Способ связи (только по выбору заявителя, только кризисные) хранится отдельно
  от текста и виден только оператору.

## Трек-номер (ТЗ 4.7)

- Формат `ОТК-XXXX-XXXX`, алфавит без визуально спорных символов (0/O, 1/I/l).
- Генерация криптостойким `secrets` — не подбирается перебором.
- Проверка статуса: до 5 попыток в минуту с адреса, при превышении — задержка.

## Уведомления (ТЗ 4.8)

- Ссылка/закладка для возврата к обращению.
- Опционально push (PWA) без привязки к личности.
- Заявитель сам решает оставлять ли способ связи (явное согласие).

## Кризисный сценарий (ТЗ 5.3)

- Детекция по словарю маркеров (насилие, угрозы жизни, суицид).
- Сразу показываются контакты экстренной помощи (не блокирует ввод).
- Кризисные обращения — отдельный блок сверху в очереди оператора.
- Предложение оставить способ связи — по желанию, не блокирует отправку.

## Список нереализованного

- PWA push-уведомления (нативная регистрация service worker не подключена).
- Автоматическая классификация на ML (используется словарь/эвристики).
- XLSX-выгрузка (есть CSV; XLSX легко добавить через openpyxl).
- Реальные WebSocket-чаты между ролями (используется REST + обновление списка).
